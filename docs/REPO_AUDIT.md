У `package.json`: Expo ~54.0.32, React 19.1.0, RN 0.81.5, TypeScript ^5.9.3, pnpm 10.12.3; є frozen lock, router, i18next, TanStack Query, UI tests та env/build profiles. Це відповідає спільній TS основі та uk/en/es напрямку, із меншою кількістю доменних екранів для видалення. Додатковий доказ — 40 тестів і фактичний export обох платформ.

**Прийняття в S1 умовне:** SHA обраний як джерело коду, не як готовий production dependency set. Registry `pnpm audit` exit 1: metadata — 9 low / 60 moderate / 101 high / 2 critical, 1765 dependencies. Це числа звіту, з повторними dependency paths, не кількість незалежних exploit або доведена mobile exploitability. Critical: `shell-quote@1.8.3` через RN devtools ([advisory](https://github.com/advisories/GHSA-w7jw-789q-3m8p)); `tar@7.5.6` через Expo CLI ([advisory](https://github.com/advisories/GHSA-23hp-3jrh-7fpw)). Є також findings для axios, transitive glob/parser packages. У S1 потрібні сумісні updates, повторні checks і disposition до прийняття; автоматичний `audit --fix` не запускався. Якщо безпечне оновлення не проходить — повернутися до рішення про основу, не приховувати провал.

Auth starter зберігає tokens у `createMMKV()` без encryptionKey; це не доказ захищеного session storage. Потрібно замінити demo auth на Supabase з належним storage у S2. `app.config.ts` містить Obytes owner/EAS projectId; `env.ts` — їх bundle IDs/schemes. Замінити в S1, не використовувати їх акаунт. ## Ingestion: адаптувати, не форкати всю апку

Переглянуті `scripts/download_feeds.py`, `combine_ics.py`, `ics_to_json.py`, `feed_slug.py`, `run_scrapers_from_db.py`, `classify_events_anthropic.py`, `scrapers/lib/base.py`, `utils.py`, tests і workflow. Є корисні source headers, URL slug collision tests, timeout/retry, ICS recurrence expansion, TZID handling і scraper abstractions. Це аргумент за Python worker із вибірковим vendoring, а не переписуванням у Node.

Проблеми, які не можна успадкувати:

- `ics_to_json.parse_ics_datetime` перетворює date-only на midnight, fallback timezone — America/Los_Angeles; unknown TZID silently falls back. Тести проходять і на цьому несумісному з MVP date-only правилі. Green upstream tests не означають відповідність нашим інваріантам.
- `utils.generate_uid` залежить від title/start: зміна назви/часу може створити новий identity. Потрібні provider/external_id, source records і стабільні occurrence IDs.
- Geo matching у combine_ics — рядкові евристики US/Canada, не глобальні адміністративні межі/PostGIS; source URLs і cities hardcoded.
- `run_scrapers_from_db` виконує DB `scraper_cmd` з `shell=True`. Не переносити довільні команди із sources registry; потрібний allowlist adapter IDs.
- Downloader/AI містять неоднорідні таймаути, глобальні env/import-side effects; AI updates SQL через psql, не готовий schema-validated provider adapter із budget.
- `requirements.txt` містить старі requests 2.27.1, urllib3 1.26.9, Jinja2 3.1.2, pytz 2022.1 та lxml 4.9.1; частина бібліотек не pinned, transitive lock відсутній. Повний security scan Python не виконаний; відсутність findings не заявляється. `make setup-python` посилається на **відсутній requirements-dev.txt**.
- GitHub Actions імпортує city дані й робить commits/push; не переносити цей workflow у продукт. Особистий UI, geocode cache, RSS/city data, admin schema та AI prompts не імпортувати.

Результат 73 tests — offline fixtures та committed upstream ICS snapshots; не доказ живих джерел чи прав на їх дані. Full install на обох локальних Python failed; для S1 worker достатньо мінімального актуального набору залежностей, для S3 — окреме виправлення нормалізації.

event-discovery: `scraper/main.py` пише Google Sheets і скорить через Anthropic; Apps Script робить Calendar/email. `collapse_recurring()` лишає лише наступну подію; `RawEvent.dedup_hash()` не включає час, тож різні сеанси одного дня з однаковими title/location можуть склеїтися. 60 tests підтверджують поведінку особистої автоматизації, не multi-user/RLS backend. Не імпортувати її backend/моделі/дедуп як є.
